# Content Style Guide

This style guide governs all product copy in the frontend experience.

## Audience
- Primary reader: parent or caregiver
- Secondary reader: child nearby while parent reads

## Voice and Tone
- Voice: warm, practical, and trustworthy
- Tone: encouraging, concise, calm under errors
- Avoid hype, fear language, or guilt framing

## Clarity Rules
- Prefer short sentences and common words
- One key action per sentence for buttons and banners
- Keep labels specific: name what happens next

## Reading Level
- UI labels and helper text target approximately CEFR A2-B1
- Error text should be understandable without technical terms

## Microcopy Patterns
- Buttons: verb + outcome ("Create Book", "Save Draft", "Try Again")
- Empty states: what this is + what to do next
- Form hints: concrete examples, not abstract instructions

## Error Message Pattern
- Start with what failed in plain language
- Follow with one concrete recovery action
- Add support direction only if recovery fails

Template:
1. "We couldn't [action]."
2. "Try [single recovery step]."
3. "If it keeps happening, contact support."

## Banned or Restricted Phrases
- "Obviously"
- "Just" when it minimizes effort or emotion
- "Invalid input" without a field-level explanation
- "Oops" in serious payment or account failures

## Inclusivity and Safety
- Use caregiver-inclusive terms ("parent or caregiver")
- Avoid assumptions about family structure
- Never expose child-identifying details in shared/public views

## Accessibility Copy Rules
- Link text must be descriptive, not "click here"
- Placeholder text cannot be the only instruction
- Success and error states must use both text and visual cues
